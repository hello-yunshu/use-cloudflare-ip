# 2.1.1 Candidate Intelligence architecture and validation

2.1.1 extends the 2.0 safety envelope without adding a second Runtime learner.
The only learned state is the generic Rill `candidate` partition with the fixed
22D schema. Source registry/profile/order/cache/scheduler logic is deterministic;
Reuse remains a Native current-IP validation hard gate.

## Lifecycle

```text
context fingerprint
  -> Native measurement and target-domain eligibility
  -> Candidate shadow / guarded-assisted preference
  -> transactional apply and post-apply validation
  -> attributed reward and delayed feedback
  -> bounded evidence store and rolling qualification
  -> confidence reasons and LuCI diagnostics
```

Context fingerprints are material-change boundaries. A changed context rotates
the Candidate lineage, resets or quarantines incompatible pending state and
evidence, while non-material configuration changes do not discard useful
evidence. A new context may re-enter Assisted only after fresh qualification.
Training feedback and evaluation evidence are separate. Holdout evaluation is bounded and non-blocking;
its outcomes are kept separate from the decision being evaluated and cannot leak
into feedback before evaluation closes. Evidence records are bounded by count
and size and are quarantined on malformed data. Holdout cadence is tracked by an
independent monotonic counter bound to the current context fingerprint and
lineage, so a bounded evidence window cannot suppress future evaluations.

Qualification is conservative and continuously rechecked. Missing, stale,
invalid, unhealthy, reset-required, resource-pressured, or incompatible Runtime
state keeps Native selection unchanged. Assisted selection is allowed only inside
the Native safe envelope and after qualification; otherwise the effective mode
is shadow or Native fallback.

## Validation contract

The host contract covers context fingerprint/reset/non-material isolation,
lineage rotation and requalification, holdout non-blocking/no-feedback-leak/
global-cadence behavior, evidence persistence/count/byte bounds and corruption
quarantine, continuous qualification, regression downgrade, confidence
consistency, status and LuCI diagnostics. CI additionally runs legacy preservation, RPC/LuCI,
workflow lint, real CFST, four x86_64 OpenWrt SDK targets, and actual packaged
generic Runtime integration.

The automated evidence chain is immutable: Cloudflare `qualification.json`
binds the exact Cloudflare SHA and CI run; the consumer pins the package-owned
Runtime contract; `rill-openwrt-packages/main` is qualified at
`64ee22f978ed8f8ed19bb675700678f57eec19e3` by run `33735123909`. Physical
OpenWrt matrix and soak are separate, explicitly approved skips.
